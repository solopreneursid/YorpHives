Product preflight.
Catch avoidable release issues.

Run automated checks against the currently published catalogue and package files before preparing a release. This checks metadata, same-site destinations, internal anchors, extension manifests and source-file availability. It does not run a real browser extension, WordPress, or VS Code, and it cannot block Hatchable's Deploy action.

Important: these checks run on the version currently published at this URL, not unsaved draft files. Run Hatchable's deployment dry-run separately. Treat a failed result as a stop-and-investigate signal; a passing result is not proof of end-to-end product functionality.
