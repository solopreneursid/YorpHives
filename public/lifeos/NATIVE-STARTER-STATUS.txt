LifeOS Native Starter — Phase 1 progress
Updated: 2026-10-27
Parent product: YorpHives / LifeOS
Starter source version: 0.2.0
Status: source scaffold updated separately; not yet compiled or tested with Flutter.

WHAT EXISTS IN THE STARTER SCAFFOLD
- Flutter/Dart app shell with Today, Tasks, Habits and Goals navigation.
- Local SQLite database, shared LifeItem model and repository boundary.
- Basic create/list/complete/delete flow for local items.
- Forward-only SQLite v1→v2 migration that preserves existing life_items and ensures support tables/indexes exist.
- Versioned JSON backup export using the shared yorphives.lifeos.backup format, version 1.
- File-based restore with validation before writes and one SQLite transaction for replacing items, habit check-ins and portable settings.
- Contract tests for envelope creation/parsing, duplicate IDs, invalid version/title and invalid habit check-in references.
- Build and release verification checklist.

BACKUP / RESTORE SAFEGUARDS
- Restore rejects malformed JSON, unsupported format versions, duplicate IDs, empty titles, unsupported item types and check-ins that do not reference an existing habit.
- Validation completes before the database is changed; replacement is transactional so SQL failures roll back.
- Restore warns before choosing a file because current local items, check-ins and portable settings are replaced.
- Only task, habit, goal and reminder item types are accepted in this starter; unsupported types are rejected rather than silently dropped.

COST-CONTROL DECISIONS
- One Flutter codebase for Android first, then other platforms after validation.
- SQLite remains the native local source of truth.
- Keep business/data logic behind repository boundaries; avoid duplicate platform-specific implementations.
- No accounts, cloud sync, telemetry or server dependency in this phase.
